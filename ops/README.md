# PRIVÉ Ops — рабочее место оператора

Реестр заказов (M2) + конвейер (сканы, доказательства, снятия, контроль) + панель. Реализует технологические карты из документа «PRIVÉ — технологические карты услуг».

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env            # вписать логин/пароль и ключи, которые уже есть
python -m scripts.seed          # демо-данные (необязательно)
uvicorn app.main:app --port 8000
```
Панель: http://localhost:8000 (HTTP Basic, `ADMIN_USER` / `ADMIN_PASSWORD`). Docker: `docker compose up -d`.

Без единого ключа всё работает в сухом режиме: заявки, заказы, разбор находок, импорт CSV, черновики жалоб, журнал. Каждый добавленный ключ включает свой шаг конвейера автоматически.

## Telegram-бот

Сценарий в `app/bot.py`: меню (Проверка / SOS / Услуги / Код для подруги / Инструкции / Мои заказы), сбор фото → кружок → ники → номер → город, заказ с ценой и реквизитами USDT, кнопка «Я оплатила» → сигнал оператору → «Подтвердить оплату» в панели. Реферальный код даёт −20% на первый заказ. SOS: три правила, пересылки сохраняются в карточку инцидента. Кружок сверяется с эталонами автоматически (модуль лица), спорные — оператору. Фото с подписью «чистить» возвращается без метаданных. Вопрос «это твоё?» по находке — кнопкой в панели.

Запуск без домена: `python -m scripts.bot_polling`. С доменом — кнопка «Установить webhook» на вкладке «Интеграции».

## Роли и журнал

Пользователи — вкладка «Команда» (admin). Роли: viewer → duty → manager → admin. Все изменяющие запросы пишутся в журнал действий. При пустой таблице работает `ADMIN_USER`/`ADMIN_PASSWORD` из `.env`.

## Продакшен

```bash
cp .env.example .env    # DOMAIN, POSTGRES_PASSWORD, ADMIN_PASSWORD, ключи
docker compose -f docker-compose.prod.yml up -d          # Postgres + панель + Caddy (HTTPS сам) + ежедневный бэкап в ./backups
docker compose -f docker-compose.prod.yml --profile polling up -d   # плюс бот через polling, если webhook не настроен
```
Тесты: `python -m pytest -q tests`.

## Что делает оператор (ссылки на SOP в документе)

- верификация кружка (SOP-3) — вкладка «Заявки»;
- поиск по лицу в PimEyes / Lenso / CamGirlFinder / Lens / Yandex Images (SOP-1, SOP-2): «Выбрать 3 эталона» отбирает кадры автоматически (одно лицо, крупно, резко, разные ракурсы, отсев чужих фото); результат PimEyes загружается кнопкой «Импорт отчёта» (PDF-отчёт, HTML-страница или текст со ссылками) — результат через «Импорт CSV» в заказе, шаблон колонок: `source,query_type,query_value,url,match_type,confidence,screenshot_file,found_at,operator`;
- SOS-разговор и чек-лист (SOP-4, SOP-6) — карточка инцидента в заказе;
- веб-формы площадок и поисковиков — `python -m scripts.form_assist <id жалобы>` открывает форму с заполненными полями и панелью с текстом; отправку и капчу делает оператор, затем «Отмечено отправленным»;
- abuse-контакт неизвестного хостера ищется автоматически (RDAP домена и IP, определение Cloudflare) при создании черновика; шаблоны для .de/.at/.ch, .it, .tr уходят на родном языке с английским дублем;
- эскалация к хостеру/платёжке (SOP-9) — статус «Эскалация», вторая волна.

## Структура

```
app/main.py          API + панель + webhook
app/pipeline.py      конвейер: скан, фиксация, снятие, повторная проверка, отчёт, тик планировщика
app/models.py        реестр: клиентки, заказы, находки, доказательства, снятия, задачи, инциденты
app/services/        адаптеры: search, leaks, evidence, takedown, telegram, importer
app/data/platforms.json   справочник площадок (редактируется из панели)
app/static, app/templates панель (без сборки)
```

## Безопасность данных

- Эталонные фото лежат в `app/data/storage/refs/<код>` и удаляются планировщиком через `REFERENCE_PHOTO_TTL_DAYS`, если нет активных заказов.
- В сторонние сервисы уходят только ники/телефоны/URL; имя клиентки в системе не хранится (поле `display` — внутренний ярлык).
- Для продакшена: PostgreSQL, HTTPS за reverse-proxy, резервные копии `app/data`, шифрование диска.
